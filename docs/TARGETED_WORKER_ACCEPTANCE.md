# Targeted worker acceptance runner

Source-only, manual acceptance preparation. No active Actions workflow, no migration applied and no secrets configured by this change.

Use `python -m lofgren_intelligence.hosted.targeted_worker --target PRIVATE_TARGET.json` only after exact-head SQL proof, review, staging migration verification, and approval of the selected synthetic case. Environment requires staging `SUPABASE_URL`, privately supplied `SUPABASE_SERVICE_ROLE_KEY`, and full accepted `LI_RELEASE_SHA`. The checkout and target application SHA must match. A clean frozen hosted install is required. Do not put the target file or key in Git, public logs, dispatch inputs or artifacts.

Private target fields: `application_sha`, `job_id`, `user_id`, `case_id`, `content_hash`, and `expected_input` (the complete already approved frozen job input). The input is compared byte-independent as JSONB inside the targeted row-locking RPC. This never claims an arbitrary queue job or runs global reclaim/reconciliation. Only fresh queued approved-case work with 1–4 labelled bounded inline texts (the native texts object schema) is accepted; external source arguments, revoked/expired or superseded approvals, wrong owner/case/hash, inactive entitlement, released reservations, prior attempts, leases and changed inputs are refused. One attempt maximum.

The child environment drops all provider keys and forces heuristic provider, zero configured retrieval/infrastructure prices and disabled external actions. It runs the existing research core; it does not grant an exception to approval, scope or budget. Output is only fixed PASS/FAIL. Child logs are discarded; source text, customer identifiers and exceptions are never echoed. The parent enforces 90 seconds then TERM, five seconds then process-group KILL and reaping. Failed/no claim, missing settings, timeout, missing receipt, incomplete job or unsettled/mismatched accounting exit nonzero. A killed job remains subject to normal lease recovery; the runner never claims that termination itself proves recovery.

New additive migration: `20261013045831_li_targeted_worker_claim.sql`. Supabase CLI is unavailable in this environment, so its UTC timestamp was generated locally following existing migration conventions; no CLI execution is claimed. It grants only service_role. Real PostgreSQL tests cover exact target, independent unrelated queue preservation, wrong identity/case/hash/input, revoked approval/released reservation/inactive entitlement, external-source refusal and competing claims. Without `LI_PG_DSN`, these tests explicitly skip and are NOT proof; CI must run them with `LI_PG_REQUIRED=1` before any staging use.

This is finite hosted integration proof preparation, not free always-on hosting or real-client acceptance. No scheduled/activated workflow accompanies it. Standard GitHub-hosted runners in public repos currently qualify for free execution; avoid larger runners, caches and artifact uploads. See `BOUNDED_ACTIONS_WORKER_PROOF.md` on design branch `task/li-actions-worker` for the manual workflow/environment gate contract.

Independent proof verification reconstructs native receipt integrity and validates knowledge-map/2 against the receipt; it does not trust the stored receipt_intact flag. Claimed and reopened job owner/case/input must equal the exact target. Saved objective/evidence passage hashes must belong to the selected inline texts. Latest persisted charter hash/version and exact consumed approval must bind the saved run; usage event/reservation IDs, owner, job, units and zero known cost must agree. No case ID/hash is invented inside the research receipt: binding uses the separately persisted approval/charter/job records, and the receipt commits to objective/evidence/knowledge state.
